# 기술 설명

## 디스크 구성

데이터 파티션의 주요 파일은 다음과 같습니다.

| 파일 | 내용 |
| --- | --- |
| `dat.bin` | 텍스트·데이터 아카이브 (130개, 홀수 번호가 게임이 쓰는 빅엔디언 판) |
| `ui.bin` | UI 텍스처(SHTX)·글꼴 아카이브 (4,296개) |
| `grp.bin` | 3D 모델(BRRES) 아카이브 (메인 메뉴 아이콘 포함) |
| `strap.bin` | 부팅 시 스트랩 안내 화면 2장 |
| `mcb0.bln` / `mcb1.bln` | 위 아카이브 파일들의 사본을 장면별로 묶은 번들 (색인/본체) |
| `movie/IEGS_OP_Wii_*.mo` | 오프닝 동영상 (Mobiclip, 4:3·16:9) |
| `sys/main.dol` | 실행 파일 |

### BIN 아카이브
헤더 `count, pad, mult, shift, mask` 뒤에 항목마다 32비트 값이 이어지고, `(v >> shift) * pad`가 오프셋, `(v & mask) * mult`가 크기입니다. 각 항목은 Shade LZ로 압축되어 있습니다(`dat.bin`은 헤더 없는 변형).

### BLN 번들
`mcb0.bln`은 `(ID, mcb1 오프셋, 블록 크기)` 목록이고, 블록 안에는 `(아카이브 번호, 아카이브 내 오프셋, 크기, 데이터)` 기록이 이어지다 `0x7FFF`로 끝납니다. 게임은 이 사본을 읽으므로 아카이브와 번들을 함께 고쳐야 합니다.

## 텍스트

- 텍스트 파일은 빅엔디언 구조(`섹션 수, 끝 위치, 섹션 표 …`)이며, 파일 끝의 재배치 표가 문자열 포인터의 위치를 모두 알려 줍니다. `tools/py/textfmt.py`가 이 표를 이용해 문자열을 바꾸고 포인터를 다시 씁니다.
- 문자열 영역이 데이터 사이에 끼어 있는 파일은, 번역문이 원문 자리보다 짧으면 제자리에 쓰고 길면 끝에 덧붙입니다.
- 인코딩은 Shift-JIS이며 `#P10#=`, `#n`, `#I1` 같은 제어 코드를 씁니다. 후리가나(`#R…(よみ)`)는 번역문에서 뺐습니다.
- 대상: `dat.bin`의 1번(메인 텍스트 7,572개), 5번(필살기 설명), 79번(필살기 이름), 87번(스태프롤), 113번(튜토리얼), 7번(스타디움) 등 35개 파일. 실행 파일 문자열 14개.

## 글꼴

`ui.bin` 0·1·2번이 게임 글꼴입니다(24×25, 4비트, 글리프마다 LZ 압축). 실행 파일의 `shdFontGet`는 Shift-JIS 코드를 JIS 구점 번호로 바꿔 글리프를 찾습니다. KS X 1001 한글 2,350자(+번역에 쓰인 1자)를 JIS 16구부터의 한자 칸에 그려 넣고, 번역문은 그 칸의 Shift-JIS 코드로 저장합니다(`tools/py/kor.py`). 글리프 표 뒤의 16단계 감마 팔레트는 그대로 둡니다.

## 그림 글자

- SHTX 텍스처(`FF` 32비트, `FS` 8비트 팔레트, `F4` 4비트 팔레트)를 PNG로 풀어 일본어 영역을 지우고 한글을 그린 뒤 같은 형식으로 되돌립니다(`tools/py/texedit.py`, `tex/spec_*.json`).
- 필살기 컷인 420장(`tools/py/mkcut.py`), 얼굴 이름표 387장(`tools/py/mknames.py`), 세로 명판 57장(`tools/py/mkvert.py`)은 규칙으로 자동 생성합니다.
- 메인 메뉴 아이콘 12장은 `grp.bin` 4686번 BRRES의 TEX0(RGB5A3·RGBA8)를 직접 고칩니다(`tools/py/mkmenu.py`, `tools/py/tex0.py`).

## 오프닝 동영상

Mobiclip `.mo`를 [mobipeg](https://github.com/star-studios-official/mobipegcustom)(Mobiclip 인코더를 포함한 FFmpeg 포크, x264 포크 필요)로 풀고, 일본어 가사 줄을 프레임마다 찾아 그 아래에 테두리만 있는 한글 가사를 한 줄 넣은 뒤 원본과 같은 640×480·24fps·PCM으로 다시 인코딩합니다(`tools/py/opsub.py`). 일본어 가사는 그대로 남깁니다. 타이틀 로고가 나오는 장면에는 로고 아래 작게 한글 제목을 넣었습니다.

## 원본 배치 유지 빌드

`wit copy`로 ISO를 새로 만들면 파일 배치가 원본과 달라져 xdelta가 3GB를 넘습니다. 그래서 다음과 같이 만듭니다(`tools/py/build2.py`, `tools/py/inject.py`).

1. 아카이브 항목은 원래 슬롯(패딩 포함) 안에 다시 넣습니다. 넘치는 항목은 최적 파싱 LZ 압축기(`tools/py/lzopt.py`)를 쓰고, 그래도 넘치는 32비트 화면은 바뀐 영역만 색 수를 줄입니다.
2. `mcb1.bln`은 블록 위치·크기를 그대로 두고 블록 안 기록만 다시 채웁니다(작아진 글꼴 사본 덕분에 여유가 생깁니다).
3. 원본 ISO를 복호화한 이미지에 바뀐 파일만 원래 위치에 씁니다. 커진 `strap.bin`만 줄어든 동영상 뒤의 빈 영역으로 옮깁니다.
4. 해시를 다시 계산하고 암호화한 뒤, 쓰이지 않는 해시 그룹은 원본 암호화 데이터로 되돌리고, TMD를 가짜 서명합니다.

이렇게 해서 xdelta가 약 410MB가 됩니다.
